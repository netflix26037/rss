# ReadSync — قارئ مواضيع RSS بحساب واحد يُزامن حالة القراءة بين الأجهزة

## التشغيل

```bash
npm install
npm start
```

ثم افتح على الكمبيوتر: `http://localhost:3000`

## التشغيل من الجوال على نفس الشبكة

1. تأكد أن الكمبيوتر والجوال على نفس شبكة الواي فاي.
2. اعرف عنوان IP للكمبيوتر (مثال على ماك/لينكس: `ifconfig` أو `ip a`، وعلى ويندوز: `ipconfig`).
3. من متصفح الجوال افتح: `http://<عنوان-IP-للكمبيوتر>:3000`
4. سجّل دخول بنفس الحساب (نفس البريد وكلمة المرور).

بما أن حالة "مقروء" تُخزَّن على السيرفر لكل حساب، فأي مقال تفتحه أو تضعه كمقروء من أي جهاز يظهر مقروءً فورًا في الجهاز الآخر عند الضغط على "تحديث".

## كيف تعمل المزامنة

- كل مستخدم له حساب (بريد + كلمة مرور، مُشفّرة بـ bcrypt) وتوكن JWT.
- قائمة المصادر (Feeds) ومقالاتها مشتركة، لكن حالة "مقروء" مخزّنة في جدول منفصل مرتبط بـ (المستخدم + المقال).
- عند طلب `/api/articles`، السيرفر يرجّع كل مقال مع علامة `read: true/false` الخاصة بهذا المستخدم فقط — فلا علاقة له بأي جهاز بعينه.

## بنية المشروع

```
server.js      نقطة الدخول + كل الـ API
store.js       تخزين بسيط بملف JSON (data.json يُنشأ تلقائيًا)
public/index.html   الواجهة (صفحة واحدة، بدون فريمورك)
```

## أول 3 أشياء أقترح تطويرها بعد ذلك

1. **قاعدة بيانات حقيقية**: استبدل `store.js` بـ SQLite (عبر `better-sqlite3`) أو Postgres — ملف JSON مناسب للتجربة فقط وسيتعثر مع عدد كبير من المقالات أو الاستخدام المتزامن.
2. **تحديث تلقائي للمصادر**: أضف مهمة مجدولة (cron أو `setInterval`) تجلب المصادر كل ساعة بدل الاعتماد على زر "تحديث" اليدوي.
3. **نشر حقيقي بدلاً من الشبكة المحلية**: انشر السيرفر على مضيف دائم التشغيل (Railway، Render، أو VPS بسيط) حتى يعمل من أي مكان لا فقط الشبكة المنزلية — تجنّب الاستضافات "serverless" مثل Vercel ما لم تُبدّل التخزين إلى قاعدة بيانات خارجية، لأن نظام الملفات فيها لا يبقى بين الطلبات.

اقتراحات أخرى لاحقة: تسجيل دخول برابط سحري عبر البريد بدل كلمة المرور، بحث ضمن المقالات، تمييز "مقروء" تلقائيًا عند التمرير، دعم تصنيفات/مجلدات للمصادر.
